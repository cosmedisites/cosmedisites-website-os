# 11. Client Strategy Deck

**Owner:** Project Lead
**Approval:** Internal unless stated

## Purpose
Present one coherent recommended direction and secure explicit decisions, rather than asking the client to solve the design problem.

## Recommended slide sequence

| Field | Entry |
|---|---|
| 01 | Cover / positioning statement |
| 02 | The aim |
| 03 | Current → proposed |
| 04 | Business outcomes |
| 05 | Visual system |
| 06 | Homepage / first impression |
| 07 | User journey |
| 08 | Distinctive brand idea / methodology |
| 09 | Priority service/category |
| 10 | Clinical team / brand architecture |
| 11 | Treatment/service page system |
| 12 | Trust / results |
| 13 | Mobile / booking |
| 14 | Photography / content |
| 15 | What we need you to approve |
| 16 | Inputs + next steps |

## Presentation rules

| Field | Entry |
|---|---|
| Rule 1 | One idea per slide. |
| Rule 2 | One sentence explains why; the visual proves it. |
| Rule 3 | Mockups should be large. |
| Rule 4 | Avoid agency jargon. |
| Rule 5 | Recommend one direction when evidence supports one. |
| Rule 6 | Finish with explicit approval decisions. |

## Quality questions

| Field | Entry |
|---|---|
| Can the client answer | What is changing? Why? How will patients use it differently? How does it help the business? What am I approving? What do you need from me? What happens next? |

## Definition of Done

- [ ] Deck tells a strategic story, not a gallery of screens.
- [ ] Business outcome is explicit.
- [ ] Client approval items are explicit.
- [ ] Inputs and next steps are separated from approval.
