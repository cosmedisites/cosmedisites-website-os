# CosmediSites Website Redesign SOP v1.0

## Purpose

Use this SOP for every strategic website redesign project.

The objective is:

**commercial brief → evidence → strategy → approved direction → build → launch → measured outcome**

The Website Strategy Playbook explains the methodology. This SOP controls execution.

## Core rule

> **Architecture follows business strategy.**
>
> **The design system follows the creative direction, not the other way around.**
>
> **SEO and CRO are constraints to design within, not excuses for generic design.**

Do not begin visual design until the business direction, positioning and site architecture are understood.

**Stage sequence (v1.1):** 00 Commercial Brief → 01 Evidence → 02 Diagnosis → 03 Positioning → 04 IA + SEO → 05 Brand + Visual Direction → 05T Creative Translation → 05V Creative Validation → 06 Page + Component System → 07 Proof + Content + Photography → 08 Client Strategy Review → 09 Approval Gate → 10 Production Inputs → 11 Build → 12 QA → 13 Launch → 14 Measurement. Stage numbers 06 to 14 are unchanged; the creative layer is 05T and 05V. See the [05T](../workflows/stage-05t-creative-translation/README.md) and [05V](../workflows/stage-05v-creative-validation/README.md) cards.

| Role | Primary responsibility |
|---|---|
| Project Lead | Delivery, timeline, client communication and gates |
| Strategist | Commercial brief, evidence, positioning, UX and architecture |
| SEO Lead | Search architecture, migrations, internal linking and search preservation |

| Developer | Build and technical implementation |
| Content Lead | Copy, content production and input management |
| Compliance Reviewer | Claims, practitioner details, treatment wording, proof |

Every stage still has **one named owner**.

# Decision hierarchy

1. **Business strategy**
2. **Positioning**
3. **UX / information architecture**
4. **Content / proof**
5. **Visual expression**

Lower-level preference should not casually overturn a higher-level decision.

# Stage 0 — Project Strategy Brief

**Owner:** Project Lead / Strategist  
**Client involved:** Yes  
**Output:** Project Strategy Brief  
**Approval:** Client confirms factual accuracy

## Capture

- Why the client hired CosmediSites
- Commercial objective
- Locations now / planned
- Current practitioners / planned team
- Core revenue services
- Services to grow
- Target patient/customer
- Current lead sources
- Booking process
- Website role in acquisition
- Known SEO priorities
- Known brand problems
- Compliance/regulatory constraints
- Technical/CMS constraints
- Deadline/scope constraints

## Definition of Done

- [ ] Business objective is explicit.
- [ ] Growth model and priority services are understood.
- [ ] Audience and buying anxieties are documented.
- [ ] Website role in acquisition is clear.
- [ ] Known SEO/compliance constraints are captured.
- [ ] Client confirms the factual brief.
- [ ] **Creative Intensity rated** (Conservative / Elevated / High-expression), scored on: audience visual sophistication; competitive visual bar; brand asset strength; purchase psychology (emotion, identity, status); commercial value (LTV, premium pricing); compliance risk (may constrain individual elements, never an automatic reason for a dull site). Scores recorded in the brief.
- [ ] **Strategic invariants captured as a short LOCKED list**: positioning, entities, service architecture, search intent, CRO paths, proof requirements, mobile CTA, compliance limits. Later creativity cannot damage these.

A GP-style practice may be Conservative; a cosmetic clinic with Instagram/TikTok-led acquisition and a premium audience is usually High-expression. The rating tells the team whether "clean and credible" is enough or whether creative differentiation is a commercial requirement.

The team can answer:

> What does this business need the new website to achieve?

And:

> What would make the redesign commercially unsuccessful even if it looked excellent?

# Stage 1 — Evidence Pack

**Owner:** Strategist  
**Reviewer:** Project Lead  
**Client involved:** No  
**Output:** Evidence Pack

## Review

- Current website
- Mobile
- Analytics/Search Console where available
- Google Business Profile where relevant
- Existing photography
- Brand consistency
- Treatments/services
- Practitioners
- Results/reviews
- Booking journey
- Competitors

## Classify

**KEEP / CHANGE / MISSING / UNCERTAIN**

## Definition of Done

- [ ] Website reviewed.
- [ ] Mobile reviewed.
- [ ] Competitors reviewed.
- [ ] Existing assets classified.
- [ ] Revenue-driving services identified.
- [ ] Growth priorities identified.
- [ ] Proof inventory started.
- [ ] Key unknowns identified.
- [ ] Strategic diagnosis drafted.
- [ ] Brand evidence gathered beyond the website: the client's Instagram/TikTok, premises photos, team, uniforms, signage and existing photography/video inventoried for Stage 05.

Required diagnostic sentence:

> "The existing site currently communicates X. The business needs to become Y. The primary barriers are A, B and C."

# Stage 2 — Strategic Diagnosis

**Owner:** Strategist  
**Reviewer:** Project Lead  
**Output:** Strategic Diagnosis

## Determine

- Current perception
- Desired perception
- Commercial weaknesses
- Trust weaknesses
- UX problems
- Brand architecture issues
- Scalability problems
- Priority opportunities

Do not prescribe visual styling yet.

## Definition of Done

- [ ] Diagnosis can be understood without discussing colours/fonts.
- [ ] Commercial, trust, UX and scalability issues are separated.
- [ ] Top three opportunities are prioritised.
- [ ] Every major conclusion traces back to evidence.

# Stage 3 — Positioning

**Owner:** Strategist  
**Reviewer:** Creative / Project Lead  
**Client involved:** Strategic approval  
**Output:** Positioning Thesis

## Define

**Three-second perception**

> "Within three seconds of landing, the visitor should understand that this is..."

**Wrong perception**

> "It should never be mistaken for..."

Also define:

- Positioning thesis
- Priority services/categories
- What the clinic should be known for
- Clinic/practitioner brand architecture
- Future-growth implications

## Definition of Done

- [ ] Desired perception written.
- [ ] Wrong perception written.
- [ ] Positioning thesis agreed internally.
- [ ] Priority services/categories identified.
- [ ] Clinic/practitioner relationship defined.
- [ ] Future growth test passed.

No visual design begins until this is internally approved.

# Stage 5 — Brand + Visual Direction

**Owner:** Designer  
**Reviewer:** Strategist / Creative Lead  
**Client involved:** Approval  
**Output:** Visual Direction / Style System

## Translate strategy into

- Colour
- Typography
- Spacing
- Photography language
- CTA hierarchy
- Card/container logic
- Iconography
- Motion
- Contrast
- Current → Proposed comparison

## Definition of Done

- [ ] Every major visual choice has a strategic rationale.
- [ ] System supports desktop and mobile.
- [ ] Photography direction is defined.
- [ ] CTA hierarchy is unambiguous.
- [ ] Client-facing explanation avoids internal design jargon.
- [ ] **Category visual benchmark**: MATCH / BEAT / AVOID board from 5 to 10 direct competitors, strong adjacent brands and the client's own social and physical brand. Not "sites we like": record visual patterns, category clichés and the current creative ceiling. For visual categories, Instagram, TikTok, clinic interiors, practitioner personal brands and adjacent beauty/fashion/hospitality brands are mandatory sources.
- [ ] **Brand reality audit**: "What does this brand look like when it isn't a website?" Brand DNA recorded: colours, contrast, image style, motion, typography, personality, distinctive physical assets.
- [ ] **Asset reality check**: USE / SHOOT / SOURCE / DO NOT FAKE matrix, and the client shoot request sent.
- [ ] **Creative thesis**: one line (HAUS: "fashion-forward aesthetics house with clinical credibility", not "premium editorial clinic"), with 3 to 5 principles and explicit anti-goals.

Client approval of the direction now happens at Stage 05V, on the keyframes, not on mood boards. Next: Stage 05T (Creative Translation).

# Stage 6 — Page + Component System (from approved keyframes)

**Owner:** Designer / UX Lead  
**Reviewer:** Strategist  
**Output:** Page System + Component Library

## Required patterns typically include

- Homepage
- Treatment/service
- Concern
- Practitioner profile
- Results/case
- Team/about
- Booking/contact

## Define reusable components

- Hero
- Trust/evidence strip
- Treatment card
- Concern card
- Practitioner card
- Results module
- Review/testimonial
- FAQ
- CTA
- Treatment facts
- Pricing
- Author/reviewer block
- Related content

## Definition of Done

- [ ] Required page types have a template.
- [ ] Core components are reusable.
- [ ] Responsive behaviour is defined.
- [ ] New treatments/practitioners/locations can be added without redesigning the system.
- [ ] **The component system reproduces the approved creative keyframes without materially flattening their visual character** (side-by-side check against 05T).
- [ ] Do not start until Stage 05V, including the asset gate, has passed.

Commodity pages may use disciplined templates; high-value pages keep bespoke visual moments.

# Stage 7 — Proof + Content + Photography

**Owner:** Content Lead  
**Reviewer:** Strategist / Compliance Reviewer  
**Outputs:** Proof Inventory + Content/Input Tracker + Photography Brief

## Proof inventory

Track:

- Qualifications
- Registrations
- Memberships
- Awards
- Reviews
- Ratings
- Before/after cases
- Case information
- Media
- Teaching/speaking
- Expert content

No evidence is invented.

## Photography

Define:

- Practitioner portraits
- Consultations
- Clinic interiors
- Treatment preparation
- Treatment details
- Natural skin
- Before/after cases

AI imagery is allowed only as clearly labelled art-direction stand-ins.

Never fabricate:

- Practitioner portraits
- Before/after results
- Credentials
- Clinical evidence

## Definition of Done

- [ ] Proof gaps are known.
- [ ] Each missing input has an owner.
- [ ] Photography requirements are defined.
- [ ] Patient/model consent requirements are identified.
- [ ] Design does not depend on evidence nobody can supply.
- [ ] The shoot brief derives from the Stage 05 asset matrix; every SHOOT item has a date and owner; nothing marked DO NOT FAKE is substituted.

# Stage 8 — Client Strategy Review

**Owner:** Project Lead  
**Presenter:** Strategist / Designer  
**Output:** Client Strategy Deck

Recommended story:

**Positioning → change → visual system → patient journey → distinctive ideas → page system → proof → mobile → photography → business outcome**

## Presentation rule

> **One sentence explains why. The visual proves it.**

Do not present several arbitrary directions when the team has enough evidence to recommend one.

## Definition of Done

- [ ] Deck tells a strategic story.
- [ ] Commercial outcome is explicit.
- [ ] Client approval items are explicit.
- [ ] Inputs/next steps are separated from approvals.

# Client Feedback Protocol

Classify all feedback before acting.

| Type | Example | Response |
|---|---|---|
| Strategic | "This does not reflect our move into dermatology." | Revisit strategy |
| Accuracy | "That is not Dr Smith's qualification." | Correct immediately |
| User / UX | "Patients will not understand this wording." | Investigate / resolve |
| Compliance | "We cannot make that claim." | Correct immediately |
| Preference | "I do not like serif fonts." | Assess against strategy |
| New information | "We are opening another location." | Assess which decisions genuinely change |

Not all feedback has equal strategic weight.

---

# Revision Control

**Round 1:** Strategic direction.

**Round 2:** Refinement against agreed strategic feedback.

Once a strategic decision has been explicitly approved, it becomes **locked**.

Reopen only when new:

- factual information
- commercial change
- user evidence
- technical limitation
- compliance requirement

materially changes the brief.

Personal preference alone does not automatically reopen previous stages.

# Stage 11 — Build

**Owner:** Developer  
**Reviewer:** Designer  
**Output:** Implemented build

Developer receives:

- Approved screens
- Responsive behaviour
- Component library
- Typography
- Colour tokens
- Button states
- Navigation behaviour
- Image ratios
- Content states
- Empty states
- SEO architecture
- Redirect requirements
- Approved copy/content
- Tracking requirements

## Definition of Done

- [ ] Developer is implementing approved decisions.
- [ ] Material UX decisions are not being invented during development.
- [ ] Desktop/mobile states are implemented.
- [ ] SEO/migration requirements are implemented.
- [ ] Tracking requirements are implemented.
- [ ] **Native implementation pilot first**: hero plus 2 to 3 core sections built in Elementor and checked for motion, imagery, responsive behaviour, Core Web Vitals, editability and visual impact at desktop and mobile. Pilot approved before rolling through the remaining pages.
- [ ] Roll-out scales without flattening: commodity pages templated, high-value pages keep bespoke moments.

# Stage 12 — Compliance + Strategy + Technical QA

Treat these as separate checks. Since v1.1 there are four independent gates: compliance, strategy/UX, technical/SEO and creative (12F).

## A. Compliance Review

**Owner:** Compliance Reviewer

Check:

- Claims
- Credentials
- Practitioner titles
- Treatment terminology
- Before/after presentation
- Testimonials
- Promotional language
- Pricing language
- Guarantees/outcome claims
- Patient consent

## B. Strategy / UX QA

**Owner:** Independent reviewer

Check:

- Positioning survives implementation
- Trust appears early enough
- User journeys work
- Clinic/practitioner hierarchy is correct
- CTAs are clear
- Mobile experience works
- Future scalability remains intact

## C. Technical / SEO QA

**Owner:** Developer + SEO Lead

Check:

- Indexability
- Metadata
- Canonicals
- Redirects
- Schema
- Internal links
- Performance
- Forms
- Tracking
- Responsive behaviour
- Broken links
- Consent/cookie implementation where applicable

## F. Creative QA (12F)

**Owner:** Independent reviewer who did not design the site

Check:

- Brand Swap Test still passes on the built site
- Built pages match the approved keyframes without flattening
- Real assets in place; no placeholder dictating layout
- Motion performant, pausable, respects reduced-motion
- High-value pages kept their bespoke moments

Route: 12A + 12B + 12C + 12F → 12D → 12E.

## Definition of Done

All four gates (compliance, strategy/UX, technical/SEO, creative) signed off independently.

- [ ] Compliance gate signed off.
- [ ] Strategy/UX gate signed off.
- [ ] Technical/SEO gate signed off.
- [ ] Creative gate (12F) signed off.
- [ ] Blocking issues resolved or explicitly accepted.

# Stage 13 — Launch

**Owner:** Project Lead  
**Technical owner:** Developer  
**Output:** Launch Record + Measurement Baseline

Capture baseline data before/at launch where available:

- Traffic
- Leads
- Bookings
- Calls
- Key landing pages
- Relevant rankings
- Conversion rates
- Mobile behaviour
- GBP/search actions

Launch only after QA sign-off.

# Stage 14 — 30 / 60 / 90 Day Review

**Owner:** Strategist / Project Lead  
**Output:** 90-Day Redesign Performance Review

## 30 days — implementation

Check:

- Technical issues
- Forms/bookings
- Mobile behaviour
- Tracking
- UX friction
- Indexation/migration

## 60 days — behaviour

Review:

- CTA use
- Treatment-page engagement
- Navigation behaviour
- Search landing pages
- Content gaps
- Booking drop-off

## 90 days — business/search outcome

Assess:

- Leads/bookings trend
- Conversion behaviour
- Priority treatment performance
- Organic visibility
- Search performance
- Content opportunities
- Commercial lessons

Decide:

**KEEP → IMPROVE → TEST → SCALE**

Feed reusable learning back into the operating system.
