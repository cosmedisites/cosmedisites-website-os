# Stage 7 — Proof + Content + Photography

**Purpose:** Build the evidence, content and image inputs needed to make the strategy believable without fabricating authority.

## 7A — Proof Inventory Builder

**Use when:** Once positioning and page needs are clear.  
**Inputs:** Existing client materials; site; reviews; credentials; result assets.  
**Produces:** Structured Proof Inventory.

```text
Build the Proof Inventory from supplied evidence.

For each item record:
TYPE
CLAIM / EVIDENCE
SOURCE
APPLIES TO: Clinic / Practitioner / Treatment / Location
VERIFIED: Yes / No / Pending
CONSENT / PERMISSION
PAGES / COMPONENTS IT CAN SUPPORT
OWNER
NOTES

Types:
Qualification
Registration
Membership
Award
Review
Patient result
Media
Teaching / speaking
Original data / study
Other

Rules:
- Never infer a credential from a biography.
- Never rewrite a testimonial as though it were verbatim.
- Never claim an award without the actual award/source.
- Separate practitioner proof from clinic proof.
- Flag expired/outdated proof.
```

## 7B — Content Gap Plan

**Use when:** When page templates are known but content is incomplete.  
**Inputs:** Page templates; Proof Inventory; current copy.  
**Produces:** Prioritised content gap list.

```text
Compare the approved page system against current verified content.

For each missing item output:
PAGE / COMPONENT
CONTENT REQUIRED
WHY IT MATTERS
SOURCE / WHO CAN PROVIDE IT
CAN WE DRAFT FROM EXISTING EVIDENCE?
RISK IF MISSING
PRIORITY
DEADLINE / STAGE

Classify:
P0 — blocks build / compliance / accurate representation
P1 — materially weakens conversion / trust / SEO
P2 — useful enhancement
P3 — post-launch opportunity

Do not create copy to fill a gap when the underlying factual evidence is missing.
```

## 7C — Photography Brief Generator

**Use when:** Before photography is booked or final design is populated.  
**Inputs:** Visual Direction; Page System; current photography; clinic details.  
**Produces:** Shoot brief and shot list.

```text
Create the CosmediSites photography brief.

Include:

ART DIRECTION
- desired feeling;
- lighting;
- environment;
- skin / retouching treatment;
- wardrobe / clinical cues;
- what to avoid.

SHOT LIST
For every required shot state:
SHOT
SUBJECT
PAGE / COMPONENT
ORIENTATION / RATIO
FRAMING / CROP
ACTION / MOMENT
CONSENT REQUIRED?
PRIORITY

Cover where relevant:
Practitioner portraits
Team
Consultations
Clinic interiors
Treatment preparation
Treatment details
Natural skin
Equipment
Before / after pairs

Rules:
- Results require real patient imagery and proper consent.
- Practitioner portraits must be real.
- AI / stock may only be clearly labelled art-direction stand-ins during design.
```

## 7D — Claims + Content Evidence Validator

**Use when:** Before client copy enters design/build.  
**Inputs:** Draft copy; Proof Inventory; compliance constraints.  
**Produces:** Claim validation report.

```text
Audit the supplied copy against the Proof Inventory and compliance constraints.

For each factual or promotional claim classify:
SUPPORTED
PARTIALLY SUPPORTED
UNSUPPORTED
NEEDS COMPLIANCE REVIEW
SUBJECTIVE BRAND LANGUAGE

Pay special attention to:
“leading”
“best”
“award-winning”
“expert”
“specialist”
“medical”
“doctor / nurse / clinician titles”
years of experience
results/outcomes
safety claims
pain / downtime claims
pricing
review ratings
guarantees

For each unsupported claim suggest:
- remove;
- soften;
- replace with verified evidence;
- request proof.

Do not invent substantiation.
```

## 7E — Client Input Request Generator

**Use when:** When content/proof/photography gaps need client action.  
**Inputs:** Content Gap Plan; Proof Inventory; Photography Brief.  
**Produces:** Prioritised client input request.

```text
Turn the current content, proof and photography gaps into one client-facing request.

Structure:
1. Needed before design/build can progress.
2. Needed before launch.
3. Useful but can follow later.

For each item say:
WHAT WE NEED
WHO / WHAT IT RELATES TO
EXAMPLE FORMAT
DEADLINE if supplied

Keep it easy to answer.
Do not expose internal priority codes.
Do not ask the client for data already supplied.
Do not combine unrelated questions into long paragraphs.
```
