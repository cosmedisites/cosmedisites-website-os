# Stage 14 — 30 / 60 / 90 Measurement

**Purpose:** Use live behaviour and commercial/search data to decide what to keep, improve, test or scale after launch.

## 14A — 30-Day Review

**Use when:** At 30 days post-launch.  
**Inputs:** Baseline; analytics; search data; issues; client feedback.  
**Produces:** 30-day implementation review.

```text
Run the 30-day CosmediSites review.

Compare against launch baseline where meaningful.

Focus on:
- tracking integrity;
- technical/indexation issues;
- redirects/migration;
- forms and booking;
- calls/enquiries;
- mobile friction;
- unexpected UX behaviour;
- major page/component defects;
- early search landing-page changes.

Output:
WHAT IS WORKING
WHAT IS BROKEN
WHAT IS UNCLEAR
IMMEDIATE ACTIONS
MEASUREMENT GAPS

Do not draw strong commercial conclusions from small/insufficient samples.
```

## 14B — 60-Day Review

**Use when:** At 60 days post-launch.  
**Inputs:** Baseline; 30-day review; behavioural data; search data.  
**Produces:** 60-day behaviour/content review.

```text
Run the 60-day review.

Analyse:
- CTA use;
- booking starts vs completions;
- treatment/service page engagement;
- concern-route usage;
- navigation behaviour;
- mobile vs desktop conversion;
- search landing-page behaviour;
- content gaps;
- high-exit points;
- proof/results engagement if measurable.

For each observation classify:
OBSERVED
LIKELY EXPLANATION
CONFIDENCE
ACTION / TEST
SUCCESS METRIC

Do not turn correlation into certainty.
Prioritise cheap, measurable improvements.
```

## 14C — 90-Day Commercial / Search Review

**Use when:** At 90 days post-launch.  
**Inputs:** Baseline; 30/60 reviews; commercial and search data.  
**Produces:** 90-day performance review.

```text
Run the 90-day CosmediSites review.

Compare:
- leads / bookings;
- conversion behaviour;
- priority service demand;
- organic visibility;
- priority landing pages;
- local/search actions where relevant;
- mobile performance;
- new practitioner/location/service scalability if exercised.

Separate:
OBSERVED — directly measured
INFERRED — likely explanation
OPEN — insufficient evidence

Then identify:
WINS
LOSSES
UNRESOLVED
COMMERCIAL OPPORTUNITIES
SEARCH / CONTENT OPPORTUNITIES
SYSTEM / PROCESS LEARNINGS

Avoid claiming the redesign caused a change unless the evidence supports that conclusion.
```

## 14D — KEEP / IMPROVE / TEST / SCALE

**Use when:** After 60 or 90-day analysis.  
**Inputs:** Review findings.  
**Produces:** Action plan.

```text
Convert the post-launch findings into decisions.

KEEP
What is working and should remain unchanged.

IMPROVE
What is underperforming with a clear fix.

TEST
Uncertain hypotheses worth a cheap controlled test.
For each include:
Hypothesis
Change
Success metric
Failure / kill condition
Test period

SCALE
What has enough evidence to justify more investment.

Order actions by:
commercial impact → confidence → speed to feedback → cost.
```

## 14E — Learning / Case Study Capture

**Use when:** After the 90-day review.  
**Inputs:** Strategy, launch baseline, post-launch results.  
**Produces:** Internal learning record and optional case-study outline.

```text
Capture reusable learning from the project.

INTERNAL LEARNING
- What did we believe at the start?
- What evidence supported it?
- What changed after launch?
- Which design/UX decisions worked?
- Which assumptions were wrong?
- What should CosmediSites repeat?
- What should CosmediSites stop doing?
- What should be added to the Playbook/SOP/template pack?

OPTIONAL CASE STUDY OUTLINE
Only use verified data:
Client situation
Strategic problem
Decision
Execution
Measured outcome
Time period
Limitations / other factors

Never manufacture attribution or percentages for marketing.
```
